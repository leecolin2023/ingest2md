感觉 AI 对一些具体指令要求识别不了和付费没关系。No，兄弟，你说这个有点模糊，就是你到底指的是哪些不行。其实我们在解决所谓的模糊输入和意图识别的过程当中呢，其实往往有几种方式。第一种方式就是通过调用一个轻量级的 API 用轻量级模型负责识别意图的，通过识别意图的话呢，能够让真正的主 Agent 在进入任务编排之前，可以先将用户的意图梳理清楚。那么第二种做法呢，也是以前比较通行的做法叫做。

我们叫重写，就用户需求重写。比如说我做卡路里记录，我说我吃了一个鸡蛋，紧接着我又说吃了一个鸡蛋。这个时候模型有可能会认为说，哦，用户可能是认为刚才的发送失败了，又重新发一个，那我到底记一个鸡蛋，还是记两个鸡蛋，这可能是个问题。那么通过重写的需求的话呢，完全可以在第二个需求上的时候，结合上下文写成用户还想再增加一个鸡蛋。你别小看这几个字的改变，在两个 request 或者两个 prompt 的这个信号强度和准确度上，立马就得到。

数据提升，后面写库就变得非常自然和简单了。如果你说它的需求和指令不清晰，识别不了。我认为大概率有可能是在 intent classification，我们叫做意图识别、意图归类，或者 rewrite 层面上，core engine 这个层面上没有做得特别好。因为有的时候用户脑子里边想的东西其实是非常奇怪的。比如说我之前做的那个日程管理的软件。我说我什么时候回北京，或者我什么时候回深圳。其实如果要重写的话，就会把它重写成用户想要查询从外地出差回深圳的航班。这个在 AI 识别的过程当中，我们叫。

signal strength，就是叫信号强度，就会非常强。因为什么时候回深圳其实是个很模糊的。唯一有价值的是那个“回”字。“回”字的意思是说，其实你的 base，你平时你家和生活、工作的基地是在深圳，回深圳是指从外地回来。那么如果你把它转写变成一个信号更强的一个 prompt，就是说用户想查询的是什么时间从外地回深圳的。那么则意味着大家在数据库里边查询的是什么？是你的 destination，我们叫目的地为深圳的所有行程，就是从软件工程上解构这件事儿，应该是这个逻辑。否则，

如果你只是用正则或者用关键字匹配，就会搜索出来什么？你从深圳飞北京和你从北京回深圳，所有的航班都会被搜索出来。所以说只有通过 rewrite 或者更加精细的 classification 才能够让用户的需求在模糊的情况之下，对于 AI 识别完成一个信号的释放和放大。然后在这个放大了的信号的情况下，再进行下一步的编排和操作，Agent 才能表现得更好。所以大家不要认为说写一个 Agent 很容易，其实不容易。你看到所有的博主在花了 10 秒钟录了一个片子，搞好了。
