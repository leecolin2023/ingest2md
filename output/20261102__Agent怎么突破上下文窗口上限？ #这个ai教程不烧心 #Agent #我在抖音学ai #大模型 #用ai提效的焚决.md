### 00:00–03:03

如何突破上下文窗口的上限，很多人的第一反应是上 RAG，或者把之前的对话总结压缩一下，再塞回去。这条路行不通，因为它有两个崩溃点，第一个叫贪多嚼不烂。很多初级 AI试图在一个会话里，把整个方案写完，结果写到一半，token 耗尽被强行截断，留下一个没写完的烂尾楼，既跑不起来也修不了，第二个叫离散失忆，发现token不够了，他会开启一个新的会话，旧会话的记忆全部丢失。新 AI面对一堆前任留下的烂摊子文件，一脸茫然只能开始瞎猜。

这时候有人会说，那把旧会话总结一下，传给新人不就行了吗？这就是摘要压缩的陷阱。你想一下，人类写代码。如果我把你1万行的调试日志压缩成500字摘要，告诉你，昨天修了个 bug有个变量不对，请问你丢失了什么？你丢失了关键的变量名，丢失了版本依赖关系。在代码世界里少一个分号程序都回放。靠这种模糊的摘要去写代码，接班的 AI只会产生幻觉，真正的工业级方案，核心逻辑其实就一句话，不要把大模型当人脑用，要把大模型当CPU用。

先思考一个问题，作为一个人类程序员，你能记住项目里每一行代码的历史吗？每一个版本吗？很难，对吧？那你靠什么工作，靠的是文件系统，靠的是 Git 仓库。所以这套架构的第一个创新点就在这环境即记忆，我们不再试图把所有聊天记录都塞进模型的上下文，而是把记忆外挂到硬盘上，我们需要持久化的日志，记录每一次报错，我们需要备份，这非常关键，它是我们的时间胶囊，我们还需要一个to do list文件告诉AI现在的进度，有了这块硬盘，模型就可以轻装上阵了。

那他具体怎么工作，这就要提到双阶段架构，阶段一初始化智能体，阶段二编码智能体。阶段一这位只在项目第一天上班。他的任务不是写代码，而是当包工头搭脚手架配环境，把环境初始化好，最重要的是建立一个进度表，把所有隐性的知识全部变成显性的文档。做完这些，他就下班了。阶段二才是重头戏叫编码智能体。这里有一个增量循环。现在的很多飞准，为什么容易死循环，因为他们贪多嚼不烂，而这个架构要求Agent一次只做一个功能。

走一遍这个循环，读取状态，写代码，跑测试，提交，读取状态，先看文件，知道自己要干嘛。写代码写完一个具体功能。好，测试这里有个核心原则叫默认失败。Agent必须假设自己写的代码是跑不通的。直到测试通过为止，这叫TDD测试驱动开发，一旦测试通过，马上可以提交就相当于游戏里的存档。那如果他失忆了怎么办？最关键的一步来了，清空上下文。每一次任务完成后，Agent会直接清空自己的聊天记录。下一轮任务开始时，它是一个全新的没有记忆。

A只要读一下刚存好的文件和 Git 历史，瞬间就恢复了出厂设置，加载最新进度。这样做的好处是什么？他把一个无限长的任务切成了无数个短小干净的片段，让token永远不会炸，成本永远可控。总结一下，记住三个原则。第一，环境即记忆别靠 prompt 长度，把记忆存到文件里去，那才是最稳的。第二，串行优于并行，与其搞一堆 AI 互相吵架，不如像接力赛一样，一个接一个，稳稳把代码传下去。第三，测试驱动，没有测试免谈。

人就是在做梦。
