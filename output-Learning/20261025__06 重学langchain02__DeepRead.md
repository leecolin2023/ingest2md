# Deep Read｜Agent 中间件、人工介入、状态和 LangGraph 流程

## 模型与工具的生命周期

讲者从 LangChain 中间件与生命周期钩子继续。模型调用前可修剪历史消息、处理上下文，调用后记录结果，再进入工具执行；工具调用前后也可通过包装函数打印参数、统计错误或执行策略。他抱怨教材反复描述同一逻辑，但所要传达的是：**业务主链之外的共性行为可以在统一生命周期位置处理**。

## 流式输出与人工中断

讲者区分流式输出不同维度：可以流式发送模型文字、工具调用事件或节点状态，不是所有流式消息都是给用户显示的自然语言。

他以“Agent 在付款前必须征得人类同意”说明 Human-in-the-loop。系统运行到需要确认的节点时先暂停，后端保留状态，前端收到等待审核的事件后显示确认弹窗。人点击批准或拒绝，前端发送恢复请求，后端按保存的检查点和决定继续执行。这需要前后端协议配合，而非简单弹一个窗口。

## 内置中间件与异常处理

课堂梳理了消息摘要、人工中断、模型和工具调用上限、备用模型、PII 隐私信息检查、工具重试、模型重试、Mock 以及运行时上下文编辑。讲者认为许多场景复用相同中间件思想：把共性控制从单一节点逻辑分离出来。

## MCP、记忆与 LangGraph

他简略提到 MCP 可以标准化工具和资源调用，批评示例缺少真正运行的服务端。随后区分会话上下文与跨会话的存储，并讨论内存型状态与持久化数据库的差别。最后回到 LangGraph 的节点、边、条件边和循环工具调用：模型决定是否继续使用工具，工具结果回到模型，直到满足退出条件。

还提到 Subgraph 将较大业务子流程封装起来，Checkpoint 支持中断后恢复，并以人工审批为恢复案例。讲者强调需要通过自己画流程图、重复读文档才能理解，而不是只浏览概念说明。

## 学习方法

直播尾声大量讨论读几遍文档、是否手写代码、LeetCode 如何准备。讲者认为先看到 API 全貌，再通过项目识别常用部分；AI 编码可代写模板，但应看懂代码。他也承认算法面试仍可能要求亲自完成编程。
