# Learning｜AI Agent 自主执行到什么程度，什么时候必须人工确认？

> 来源：output/20261025__2.26 武汉边缘面试官18k/content.md。Learning V0.7.0；独立 Review 隔离未验证。

## 为什么“越少确认越先进”不是通用规律

Agent 的权限不应只按技术能力决定，还要考虑**行为可逆性、财产风险、数据敏感性、用户授权与法规责任**。

查天气、整理草稿等低风险只读任务，可以高度自动化；提交采购单、向客户发通知、转账或删除数据等有副作用任务，则需要依据已授权的规则设置审批和限额。即使是买咖啡，是否能自动下单也取决于事前支付授权、金额上限、收货信息与用户是否允许重复购买。

## 不一定每次都弹窗

“人工介入”可以是高风险操作逐项确认，也可以是用户事先批准一定时间内的受限自动执行。例如允许每周工作日购买价格不超过 30 元的固定咖啡，但修改支付账户或超额度必须重新确认。这样既控制风险，也避免所有步骤都繁琐弹窗。

## 把权限落在宿主，而非模型自觉

模型说“我已经获授权”不能作为执行证明。后端应检查真实用户身份、授权范围、操作金额与幂等状态，记录审批结果和审计日志。在 LangGraph 等工作流里可以用 interrupt 暂停执行，但审批规则应由可信业务服务检查。

## 怎样评价 AI“核心性”

AI 客服是不是核心，取决于业务是否依赖该能力、为用户解决了什么痛点、是否带来可验证价值；不能由产品使用了多少 Agent 技术或对人工确认的态度直接推导。

招聘对话中的“边缘”标签和对公司福利的争论，需要分别基于产品证据和正式用工信息判断。真正重要的技术问题是**自主性、信任和业务责任如何设计**。
