# Learning｜Agent 的动态模型路由和 Mock 测试分别解决什么工程问题？

> 原稿：`output/20261025__31 自媒体运营Agent 4_ev/content.md`。Learning V0.7.0；独立 Review 调用隔离未验证。

## 模型路由为什么需要基于任务

一个内容 Agent 可能需要“提炼五个标题”“撰写两千字长文”“判断是否违背品牌规范”。它们对推理能力、输出长度、格式和时延的要求不同。模型路由可以依据任务类型、难度和预算，选择小模型或大模型，兼顾质量与成本。

但不能只凭“输出短就使用小模型”：短的法律判断或金融数字核验可能比长篇宣传文案更难。路由策略需要根据每类任务的**正确率、耗时、价格与失败代价**测试。

## Mock 模式如何缩短开发反馈环

若图片生成需要一分钟，修改一次工作流连接就执行全部真实节点，会大幅拖慢调试。Mock 节点可以固定返回一张示例图的 URL、一个符合 Schema 的文本结果和任务 ID，使开发者快速测试分支、数据传递、Checkpoint 与前端状态展示。

但 Mock 数据过于理想时也会掩盖真实超时、内容违规、模型 JSON 不合法、上传失败等问题。因此至少需要两层测试：

- Mock 测试：快速验证流程状态、字段与分支；
- 真实 API 集成测试：检验限流、输出格式、延迟、费用、失败和恢复行为。

开发环境与生产环境的开关必须明确隔离，避免线上误用假素材。动态路由和 Mock 共同降低成本，却解决的是**运行期选择模型**与**开发期替代依赖**两个不同问题。
