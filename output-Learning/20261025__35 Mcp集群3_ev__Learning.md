# Learning｜RAG 多项目隔离与长期用户记忆，为什么不能只靠一个命名空间？

> 来源：`output/20261025__35 Mcp集群3_ev/content.md`。Learning V0.7.0；独立 Review 隔离未验证。

**项目知识库**和**用户长期记忆**是不同的数据对象。前者记录业务文档、产品知识、权限；后者可能包含用户偏好、历史选择和个人信息。二者都可被检索，但更新方式、访问授权和删除要求不同。

命名空间或 Collection 有利于按项目组织数据，却不能自动构成强隔离。查询阶段仍应检查应用身份、租户 ID、文档权限和数据用途；管理后台和日志也必须受控。

跨系统记忆需要更严格的前提：账号关联是否得到确认？用户是否同意不同产品复用资料？记忆内容如何纠错、过期和删除？哪些敏感信息绝不能自动推断或转发？

例如用户在购物应用里提到食物过敏，不应该默认让一个无关应用读取并使用该信息。即使技术上可以通过同一 `user_id` 找到数据，合法访问权限仍必须由产品与安全规则决定。

实现上可以让 RAG 知识服务与记忆服务分开，再由用户授权层统一控制访问。只有明确的跨产品需求和授权治理出现后，才应把它从“预留架构”升级成真正启用的业务功能。
