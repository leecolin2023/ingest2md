# Learning｜多模型平台为什么要统一代理 API Key、路由和额度？

> 原稿：`output/20261025__34 MCP集群2_ev/content.md`。Learning V0.7.0，独立 Review 隔离未验证。

如果每个业务团队单独保存云厂商 API Key，会发生凭据散落、权限难撤销、成本难归属、供应商切换困难等问题。统一模型网关可以把应用身份与上游供应商密钥分离：

业务应用使用组织内的短期凭据或服务身份调用网关；网关检查权限、选择模型、代持供应商密钥并记录用量。这样撤销某个应用的权限，不需要把供应商主密钥发给所有开发者。

选择模型时还要考虑能力类型：对话生成、Embedding、Rerank、图像理解不能只依靠价格排序；必须验证输入输出协议、延迟、质量与版本。

一个需要澄清的概念：**MCP 工具服务不等同于统一 LLM 推理 API 网关**。模型网关通常提供 OpenAI-compatible 等推理接口；MCP 可以把某些能力作为可发现工具暴露给 Agent。是否需要两者，取决于业务调用方式，而非所有模型都必须包装成 MCP Server。

验收时应检查 Key 不出现在客户端日志和源码中、每个应用有独立授权和配额、调用能准确记账、上游故障可追踪。
