# Deep Read｜数据中台如何同时服务 RAG、微调与多模态素材

> 源稿：`output/20261025__24 数据中台3_ev/content.md`（6分20秒）。Deep Read V6.4，按多个独立认知单元恢复。

讲者先解释“一键清洗”：针对某类业务选定策略，执行机器过滤、人工清洗和人工补充，形成可导出的数据集。不同下游业务可以对应策略 A/B/C，人工复核与补充内容也会有所不同。

随后他把数据中台扩展为多个 AI 项目的共同上游。客服系统需要 RAG 知识库数据；模型微调可能需要 SFT 或 DPO 训练数据。讲者粗略区分：SFT 提供示范性输入输出或完整对话，DPO 还要比较偏好的回答与较差的回答。他要求学员进一步弄清这两种训练数据的具体字段结构，而不只是背缩写。

然后是媒体资产的流转。素材管理中心保存商品图片和视频，自媒体运营 Agent 生成新宣传图片后，资产也可以关联到 SKU 并补充进入数据中台。AI 客服检索文字、图片或视频时，都利用商品 ID 找到对应材料。

最后他强调多个项目并非孤立演示，而可以由统一的数据中台打通：**清洗对话 → 生成知识/训练数据 → 媒体资产关联 → 客服与运营共同使用**。视频没有具体实施跨系统接口和数据同步细节。
