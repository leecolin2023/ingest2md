# Learning｜为什么 RAG 评测不能只保存问题和最终答案？

> 来源：`output/20261025__18 评测集1_ev/content.md`，遵循 Learning V0.7.0；独立 Review 隔离未经验证。

传统确定性函数的测试通常能直接比较输入、期望输出和实际输出。但 RAG 的最终答案还受到**检索到哪些证据**的强烈影响。若系统答错，有两种截然不同的可能：它没有找到正确资料；或者找到了资料却解释错了。

因此，至少记录 `question`、`retrieved_contexts`、`answer`；进一步还应记录知识库版本、相关片段 ID、参考事实、模型与检索配置。

示例：用户问“这款鞋还有 42 码吗？”如果 RAG 片段里没有库存记录，就属于信息来源缺失；如果返回的权威资料明确说没有 42 码，而模型说“有”，则是生成不忠实。只看“有/没有”的最终回答，无法快速区分责任链路。

这也说明，讲者提出的三元组是理解 RAG 评测的有用起点，却不等于全部评测要求。没有 RAG 的模型调用仍可能需要安全、格式、任务完成率或业务正确性评测。评测对象应该由业务目标决定，而不是由系统是否使用知识库决定。
