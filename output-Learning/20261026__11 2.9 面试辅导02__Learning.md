## 一个有审核的生成工作流如何运行

运营下达“生成产品主图与文案”，主图 Agent 根据已授权 SKU 数据生成素材，文案节点产生草稿，人工审核决定批准、修改还是拒绝。重要的是**审批不由模型自称完成**，而应有后端持久化状态与授权验证。LangGraph interrupt 可在业务控制点暂停，Checkpoint 可保存执行状态；恢复请求绑定任务 ID、产物版本和审批者，避免旧版本通过后误发布新版本。

Subgraph 用于把复杂的图片、文案或视频生成拆成相对独立的业务子流程。它不是必须添加的技术标签，应由数据状态和团队维护边界决定。

## 为什么生成 API 需要 Mock、限流和可靠性控制

图片/视频生成耗费时间和费用，开发时可以用 Mock 返回符合接口格式的示例结果来验证节点状态。正式联调必须关闭 Mock，验证真实服务的回调、超时、失败、费用与幂等。

生产保护包括用量预算、速率限制、超时、有限重试、熔断与降级。健康检查用于判定服务是否能继续接单，但简单的存活接口不能证明整个下游图片服务可用。

## RAG、SFT、DPO 的对象完全不同

RAG 在推理时检索版本化知识，适用于会变动的商品价格和规则。SFT 用优质样例训练回复行为，适合较稳定的语言习惯和输出格式。DPO 通过 chosen/rejected 偏好对强化回答选择，例如投诉处理时更注重证据和同理心。

微调后模型不自动知道今天的库存，所以仍需 RAG 或业务接口；而 RAG 放进一套销售对话也不能保证模型长期学会完整销售策略。

## 如何验证产品真实有效

分别评价内容被运营采纳的比例、图片链接有效性、任务恢复与审批越权、每个有效作品的成本；对微调则用独立持出集比较风格、事实错误和多轮稳定性。面试只能将真实做过的工作写成已完成，模拟或假设应明确说明。
