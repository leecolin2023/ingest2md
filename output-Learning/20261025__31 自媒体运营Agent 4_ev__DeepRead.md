# Deep Read｜动态模型路由与 Mock 开关如何帮助 Agent 开发

> 来源：`output/20261025__31 自媒体运营Agent 4_ev/content.md`（4分58秒）。Deep Read V6.4。

讲者先解释“多模态动态路由”：一条 Agent 工作流中有轻重不同的子任务。把文章提炼成一个爆款标题，只需要较短输出，可能交给轻量模型；把大纲拓展成长文章、处理复杂内容时，则考虑更强的模型。这是**根据任务难度选择模型**，而非所有节点固定使用旗舰模型。

讲者随后略过结构化输出与 Token 统计兼容等文案，认为没有必要为了写简历而夸大这些技术细节。

本节后半段重点是**环境变量驱动的 Mock 开关**。LangGraph 工作流可能有十几个节点，若每次调试都真实生成图片与视频，耗时和费用很高。开发阶段可开启 Mock 模式，用预先准备的假图片、文字、视频记录快速跑完整链路，验证节点连接、输入输出字段和分支跳转；开发完成后再关闭 Mock，用真实 API 运行集成测试。

讲者还顺带提到 Swagger UI 等本地接口调试工具与公网映射工具，但没有深入展开。

全文由两个工程直觉构成：**昂贵模型要按任务需要使用，昂贵外部调用要能在开发期被可控地替代**。两者共同服务成本和研发效率，后者不能替代正式真实服务验收。
