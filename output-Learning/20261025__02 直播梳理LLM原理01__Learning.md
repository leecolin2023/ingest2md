# Learning｜一个 LLM 怎样训练出来？梯度、MoE 与蒸馏改变的是哪一环？

> 来源：output/20261025__02 直播梳理LLM原理01/content.md。依据 Learning V0.7.0，独立 Review 模型调用隔离记录未验证。

## 训练不是“读完资料就会回答”

语言模型首先把文本转换为 Token，再通过层叠的神经网络计算每个位置的预测分布。预训练中常见的训练目标是预测后续 Token。模型不会简单把整本书作为结构化数据库保存，而是在优化过程中让权重形成有助预测的统计和语义规律。

一轮优化可以理解为：

1. 准备训练样本及监督目标；
2. 前向计算得到预测与损失；
3. 使用自动微分和反向传播求损失对可训练参数的梯度；
4. 优化器根据梯度、学习率等更新参数；
5. 重复直到训练达到目标或预算限制。

**反向传播求梯度，优化器更新参数**，这两个动作不同。学习率调整的是更新步幅，不是每秒更新多少次。

## 为什么模型可能过拟合

若训练集里某种偶然特征与标签总一起出现，模型可能学到这种错误捷径，在新数据上失败。Dropout、权重衰减、数据多样性和持出集验证都用于降低过拟合风险。Dropout 是训练时按概率屏蔽激活的正则化手段，并不是保证任何“大模型记忆”都正确的通用方法。

## MoE 解决哪一种成本问题

Dense 模型通常每个 Token 经过相同的主要参数路径。MoE 将部分前馈计算组织为多个专家，由门控路由选择其中少数专家参与计算。所以**总参数数目可以较大，而单 Token 激活的参数子集较小**。代价可能是专家负载不均、跨卡通信、路由稳定性以及部署调度复杂。

MoE 不是让一个专家只管“情绪”、另一个只管“法律”的固定业务分类；专家的功能通常由训练自发形成。

## 蒸馏与量化、RAG 怎么区分

蒸馏让学生模型学习教师模型输出/概率分布/推理行为，改变**学生模型的训练结果**；量化压缩数字表示，主要改变**模型存储与计算方式**；RAG 在运行时加入知识证据，通常**不改变模型参数**。三者都可能降低某一成本或改善某一任务，但机制不同。

## 工程师需要怎样使用这些概念

遇到慢的问题先判断是权重装载、Prefill、Decode、调度或外部 API 瓶颈；遇到答错的问题判断是知识缺失、检索证据不足还是模型生成错误。知道训练机制不能直接推出具体机器价格、质量或吞吐，仍要根据模型结构、数值精度、KV Cache 和实际负载测算。
