# Learning｜RAG 召回率低，先改 Query、Top-K，还是检索架构？

> 原稿：`output/20261025__12 如何提升召回率？_ev/content.md`；按 Learning V0.7.0 解释因果机制，未取得独立 Review 隔离执行记录。

召回率低，意思是**原本应该找到的证据没有进入检索候选集**。要改进它，首先要知道漏掉证据的原因。

## Query 改写修复的是输入不完整

“那台电脑玩足球卡不卡？”如果上文刚讨论某款游戏本，查询只保留“那台”，就无法正确锁定产品。Query 改写可以结合已经确认的 SKU 和上下文，将句子扩写为“某型号游戏本运行指定足球游戏的流畅度”，使全文或向量检索得到足够多的定位信息。

但改写不应擅自添加用户没有确认的型号或游戏。如果历史对话里有两个候选，澄清比瞎猜更可靠。

## Top-K 增大为什么不一定更好

假设正确文档目前排在第 18 名，Top-K=10 会漏召，K=20 可能找回它。然而，增大 K 也会把更多噪声送到重排模型，使时延和成本增加；如果相关片段根本不在索引里，K 从 10 增大到 100 也无济于事。

因此应该看 Recall@K 曲线，而不是把“越大越准”当成普遍规则。

## 混合检索改变的是匹配通道

BM25 等词法检索对型号、编号、错误码更敏感；向量检索可以发现同义和语义相近的表达。两路召回并去重，可以减少单一通道的漏召。后续再用 Reranker 判断哪些片段更切题。

## 实际排查顺序

先在黄金测试集上检查每个失败问题的**目标证据 ID**是否存在、当前可访问和索引最新；再查看 Query 是否缺信息，过滤条件是否把正确资料排除；最后逐个比较 Query 改写、Top-K 和混合检索的效果。保留同一套评测数据与目标指标，才能说清是哪一项改动真正提高了召回率。
