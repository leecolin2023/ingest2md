# Deep Read｜上海 35K 二面：从商品问答迁移到酒店服务 Agent

> 来源：output/20261025__4.23 上海35K实战面试-2面裁切/content.md（约51分54秒）。Deep Read V6.4，Coverage-Preserving。

面试官先要求候选人解释销售对话从微信/私域记录导出后如何加工。候选人介绍数据中台、机器清洗、人工标注、质量评分，再按用途生成 RAG 知识、SFT 示范对话及 DPO 偏好样本。双方进一步讨论客服用户“不满意”反馈如何回流到知识库、评测集或运营人员复核，以及商品标签、价格库存从哪个系统取数。

面试官指出电商客服多数只是回答商品信息，退货、订单处理实际上依赖 Shopify 等外部系统。于是引入酒店 AI 前台的更复杂设想：同一段对话不仅回答早餐厅位置，还要完成入住、续住、退房、衣物送洗等多步业务。

这里出现核心追问：用户在办理入住的中间步骤，突然问“洗衣房在哪里”或者要求送洗，怎样判断意图并在不同流程间切换，同时保留未完成入住任务的状态？候选人建议通过意图识别、独立的业务流程 Agent 和可恢复状态协调，让一个聊天窗口服务不同任务。

后面双方讨论 MCP 是否应承载业务 API、通用模型工具、用户长期记忆与数据访问。候选人主张模型和知识等共性能力统一服务化，业务逻辑仍由具体应用治理。面试官继续追问长期记忆的压缩与跨系统数据共享授权。结尾是岗位方向与是否还有后续技术面试的沟通。

整场从数据准备进入实质业务服务，强调了多意图、多任务状态和跨系统责任问题。
