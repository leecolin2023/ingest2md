# Deep Read｜从微信聊天记录到高质量业务原数据

> 源稿：`output/20261025__22 数据中台1_ev/content.md`（5分34秒），SenseWright Deep Read V6.4。

讲者将此前的 AI 客服项目与“数据中台”连接起来：客服知识库不是凭空出现，而是从微信销售沟通记录中加工出来。

第一步，使用工具将微信消息导出为 SQLite 格式，再转换到 PostgreSQL 中。讲者将这一层理解为可保存、可继续处理的原始数据备份，强调原始记录与后续加工产物应分开。

第二步编写 ETL 清洗策略。机器可依据时间、关键词、业务类型等规则过滤记录。这些规则可以通过 Python 脚本执行，也可以配置成界面，让业务人员选条件后统一清洗。

第三步进入人工复核和标签。讲者让人工区分记录是成交还是咨询等类型，并对数据质量进行高、中、低分级，过滤无效对话。

第四步人工补充。例如客户历史上从没明确问过“课程是否对标大厂”，但产品确有相应卖点，就可以由工作人员人工补写结构化知识，不必局限于已有聊天原话。最终生成一份经过机器与人工协作处理的业务数据表，供后续 RAG 或其他应用使用。

认知推进为：**源数据导出和备份 → ETL 机器过滤 → 人工打标签与分级 → 人工补充缺失知识 → 业务知识原表**。讲者没有提供完整的数据结构或数据量实测。
