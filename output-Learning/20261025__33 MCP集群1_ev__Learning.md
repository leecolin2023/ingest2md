# Learning｜MCP 网关和普通 API 网关有什么相同与不同？

> 来源：`output/20261025__33 MCP集群1_ev/content.md`，Learning V0.7.0；独立 Review 隔离未验证。

MCP 为 AI 应用和工具/资源提供标准化交互契约；当企业同时存在许多工具服务时，还需要统一治理其接入、认证、权限和调用可观察性。网关承担的认证、限流、路由等职责，与传统 API 网关有共同点。

特殊之处在于 Agent 会**动态发现并调用工具**。因此必须分别控制“模型可以看到哪些工具描述”和“执行时当前用户/应用究竟有权调用哪些工具”。仅在提示词里隐藏工具名不等于后端授权。

一次受控调用可以分为：应用身份认证 → 用户与租户上下文传递 → 可用工具列表过滤 → 工具名与参数校验 → 执行权限检查 → 配额与限流 → 调用追踪与审计。

例如客服 Agent 可调用商品库存查询，但不能看到内部薪资查询；即使模型伪造工具名或参数，也应在网关和下游服务端被拒绝。应用配额也不能仅统计 Token，还要考虑外部 API 次数和高成本工具调用。

验证时应包含越权工具发现、跨租户调用、参数注入和突发用量，而不只是成功请求是否能路由到目标 MCP Server。
