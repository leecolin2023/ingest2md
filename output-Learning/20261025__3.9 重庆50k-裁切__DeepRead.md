# Deep Read｜重庆高薪面试如何围绕语音客服深挖 RAG 与小语种

> 来源：output/20261025__3.9 重庆50k-裁切/content.md（约32分48秒）。Deep Read V6.4，Coverage-Preserving。

候选人介绍跨境电商前后端开发经历和近两年的 AI 客服、运营图片生成、销售数据微调。面试官选择实时语音系统深挖：RTC 建立音频连接后，用 ASR 把用户语音变文本，大模型结合 RAG 检索商品知识，再由 TTS 合成结果返回；候选人表示使用火山引擎成熟服务。

之后讨论知识库构建与性能：按固定 Chunk 切片可能截断关键句，因此考虑更适合业务问答的分段策略；向量维度从较高值下降、使用混合检索、重排，以及产品查询的特点。候选人将知识库语气与系统提示词不一致联系到模型回复延迟，也介绍热词设置、ASR、TTS、RTC 等环节的优化。部分推论缺少对照压测。

接着面试官问为什么微调，候选人称希望让通用模型更接近真人销售，承认云端基座版本升级可能使训练收益过时。随后讨论 LangGraph Checkpoint 的状态持久化、Agent 运行效果评测，候选人介绍每天抽取请求评估回答忠实度和切题程度。

临近结束，面试官进一步提出**跨境小语种文本客服**的情景：如果模型不认识某个语种、RAG 文档又来自不同语言，要如何设计？候选人的回答在“底座无法理解”与“业务文本语言适配”之间没有完全区分，面试官没有给出现场确定结果。候选人随后又电话询问招聘所标 50–70K 区间是否属实，直播复盘推测面试表现。

全场问题链为：**项目背景 → 语音链路 → 知识分段/压缩/检索 → 微调 → 评测 → 小语种业务适配**。
