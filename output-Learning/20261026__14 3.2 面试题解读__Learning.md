# Learning｜面试官连续追问 RAG、Agent 和微调，怎样用可验证的项目逻辑回答？

> 原稿：output/20261026__14 3.2 面试题解读/content.md。遵循 Learning V0.7.0 的知识主干；未获得独立 Review 隔离运行记录。

## 先将系统职责说清楚

客服知识库是为用户提供商品说明的应用；内容运营 Agent 以工作流生成文本或图片；微调则是一种改变模型行为的训练手段，可以服务客服却未必需要成为独立业务系统。只有理解各自输入、输出与责任，面试才不容易把多个技术标签讲成同一件事。

## 模型接入模式要说到具体边界

调用云端模型 API、在本地部署模型、使用托管 RAG 与自己搭 PostgreSQL + pgvector，各自责任不同。云端 API 需要处理鉴权、限流、供应商配额及数据治理；本地服务还要承担权重加载、显存、模型进程、监控和推理引擎适配。不能把“使用了模型”理解成“自己部署了推理服务”。

## 评测是定位链路问题

RAG 看证据召回、精排和答案忠实；媒体生成看画面与 Prompt 及业务规范；Agent 看工具执行和人工审核是否遵循约束。设置可复现样本与版本，才能在改动后回答“确实改善了什么”。

## 复杂 Query 为什么可能需要拆分

用户提出一个跨三个商品、预算、保修条件的复合问题时，直接用整段文字做一次向量检索，可能弱化其中一些子要求。可以先结构化识别实体与子问题，分别检索对应证据，再汇总比较。但是否拆分，以及拆到什么粒度，需要用真实问题集测试，并非所有长问题都必须分解。

## 训练数字与职业背景必须真实

显卡、样本、训练轮次、耗时和指标应有真实日志；没有做过的写成实验或设计。背景调查范围依企业、地区和授权不同，不能假设“只有社保可查”就能放心虚构企业。用真实工程决策逻辑回答追问，比预先背一套随意编造的数字更可持续。
