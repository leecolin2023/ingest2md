## 把几个项目拆开解释

讲者先面对学员上传的面试问题：智能客服、自媒体运营、微调是否算同一项目的三个阶段？他认为前两个本就是不同业务系统，而微调可能作为客服能力改造的延伸，不能机械归为三个时间阶段。讲者鼓励学员把这几套项目拆开讲清起因与用途。

## 如何回答技术追问

他逐项回应面试问题，包括 RAG 用的托管 Viking 知识库还是自建数据库、LangChain 和 LangGraph 的工作流与 Agent、模型是在云端 API 还是本地部署、生成结果怎样评估。他建议抓住三类评测：文本忠实和切题、图片与提示词匹配、Agent 流程轨迹，并在优化问题中描述模型、知识库、延迟、日志和部署多个层面。

关于很长的复杂用户提问该如何分解进行 RAG 检索，讲者承认自己不确定、还需再研究，这是原文少见且应保留的知识边界；不能把未解的问题写成已解决技术。

## 虚构指标和背景调查

讲者建议在面试中罗列大量技术亮点、让面试官没有时间深入追问。他还给出本地和云端模型微调的显卡、轮次、样本条数与耗时示例，并直言可以随意编造。他认为背景调查主要查社保和犯罪记录，教授如何解释公司工作经历、工资和社保不匹配。上述数字和背景调查口径没有可靠证据，且不少属于故意虚构，不应作为真实项目说明。

## 求职话术与技术事实的差别

本节真实的推进是**项目分类 → 技术问题串讲 → 不熟悉的复杂 Query 问题 → 微调数字包装 → 背调与求职宣传**。有助于学习的部分是将技术问题放进真实业务链；需要警惕的是把提示词或简历润色当作已经做过的工程实践。
