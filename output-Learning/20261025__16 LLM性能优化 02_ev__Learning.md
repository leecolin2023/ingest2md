## 同一批知识片段，顺序为什么可能影响输出？

向生成模型提供的上下文不仅是一组无序文件，**Token 顺序本身就是输入的一部分**。即使三条片段完全相同，前后次序变化也可能影响模型关注与引用位置。因此不能仅因为“都给了模型”就断言顺序与答案无关。

若希望稳定前缀缓存，应区分**召回相关性排序**与**缓存排序优化**。更安全的办法是把完全稳定的系统指令置于前缀，把频繁变化的 RAG 内容放后面，而不是为了命中缓存随意打乱证据重要性。是否值得对证据稳定排序，要通过答案质量与缓存效果共同验证。

## Temperature 与输出 Token 分别管什么

Temperature 调整生成采样分布的随机性，较低值通常更偏向高概率 Token，但设为 0 并不构成业务正确性保证。对结构化意图识别，优先采用 Schema 验证和业务约束；对客服回复，再根据语气与事实准确性选择合适设置。

`max_output_tokens` 限制单次输出的 Token 数量，生成更短一般能减少 Decode 时间，但若上限太小，会截断答案。它与提示词里的“200 字以内”并非严格一一对应：中文字数不等于 Token 数。

## 一次生成，分三次显示意味着什么

模型可以输出三段文字，服务器按分隔符拆分，再通过 SSE 推送三次消息。这使界面看上去更像即时聊天，但本质仍是一轮推理。如果等模型全部生成后才开始逐段推送，**真实模型完成时间没有变**；如果边生成边解析边推送，才可能降低首段可见时间。

对语音客服，需区分文本首 Token 时间、句段就绪时间、TTS 首包时间和语音播放开始时间。优化交互体验，不等于模型计算吞吐提升。
