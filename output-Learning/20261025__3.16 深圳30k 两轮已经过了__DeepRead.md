# Deep Read｜深圳 30K 面试如何在 AI、前端与部署能力之间交叉验证

> 来源：output/20261025__3.16 深圳30k 两轮已经过了/content.md（约83分19秒，含较长的直播闲聊）。Deep Read V6.4，Coverage-Preserving。

面试先从电商经历和 AI 项目展开。候选人介绍跨境电商、AI 实时客服、产品知识库、运营生成图片、模型微调及评测。面试官追问公司研发角色、存储组件、知识库是托管还是自建，候选人解释利用火山引擎知识库与飞书文档同步，运营人员通过维护有格式要求的文档更新业务知识。

接下来面试官转向 LangGraph Checkpoint、长期/短期记忆、Prompt 优化。候选人用运营工作流“选风格—生成图片—人工确认—持久化状态”举例，主张把 PostgreSQL 接到 Checkpointer 以支持页面刷新后的任务恢复。他还声称客服性能优化来自模型版本选择、提示词简化以及知识库文风一致等。

随后出现与 AI 项目不同的**前端基础与交付工程追问**：按钮重复点击怎么处理，是否知道防抖、节流；布局和 CSS 的 gap 等细节；CI/CD 如何将镜像推到云镜像仓库、触发服务部署、健康检查与自动扩容。候选人承认部分前端属性不熟，解释之前使用的 loading 禁用方案和云端部署流程；这些回答展示了架构层理解，但部分服务平台术语、自动扩容指标与亲自操作细节未得到演示验证。

结束时面试官口头表示有继续沟通的可能，候选人进入直播点评与课程推销，讨论学历、岗位薪资、AI 趋势和学习方法。直播中的学员成功案例、工资预测、课程效果排名均属于讲者声称，不是当场可审计的招聘数据。

本场的关键推进是：**AI 产品全景 → 具体存储/知识库/状态持久化 → 生成与性能优化 → 前端交互 → CI/CD 和云端部署 → 岗位匹配**。真正考察的是候选人是否拥有贯穿端到端交付的工程能力。
