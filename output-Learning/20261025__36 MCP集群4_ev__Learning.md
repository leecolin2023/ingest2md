# Learning｜MCP Prompt、Resource 与会话数据库分别负责什么？

> 原稿：`output/20261025__36 MCP集群4_ev/content.md`。Learning V0.7.0，独立 Review 隔离未验证。

**Prompt 模板**用于组织可复用的交互指令，例如客服角色、语气和业务回答边界。模板可以按名称、版本和参数管理，调用时填入明确允许的变量。

**MCP Resource** 是服务端向客户端提供可读取内容的机制；它可以暴露某个文档或记录的视图，但不等于完整的会话数据库。对于需要搜索、修改、写入的动作，往往还需要工具调用或专用业务 API。

**会话持久化**负责记录用户消息、上下文状态、任务进度和权限。存储通常要有用户/租户、会话 ID、创建与失效时间、数据访问审计，而不是把聊天记录塞进一份长期公共 Prompt。

假设用户再次打开客服窗口：服务端先以已认证的用户身份定位会话，取出必要历史和当前 SKU 状态，再选择业务 Prompt；若需要访问资料，则由受控工具或资源服务提供数据。不同用户不能因为知道相同的对话 ID 就读到别人的内容。

这三个机制各司其职：**Prompt 规定怎么交互，Resource 提供可读内容，会话存储记录用户状态**。统一管理只有在访问控制、版本治理和数据隔离也清楚时才有价值。
