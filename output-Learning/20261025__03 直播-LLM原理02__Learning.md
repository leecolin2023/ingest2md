# Learning｜Transformer 为什么可以理解上下文，又怎样接入图片与声音？

## Token 进入 Transformer 后发生什么

输入文本首先转换为 Token ID，再映射为向量。模型还需要某种位置信息，否则单纯的注意力不能完整表达“谁在谁之前”。不同模型可能采用绝对位置编码、相对位置编码或旋转位置嵌入，并非只有原始正弦/余弦方案。

自注意力让各位置通过 Query、Key、Value 计算交互权重，选择与当前预测相关的上下文；多头机制让多个表示子空间并行参与关系建模。FFN 在每个位置上做非线性变换，增强表示能力。残差与归一化等设计帮助深层网络维持稳定的信号和训练。

## 为什么 GPT 是单向生成但仍有自注意力

“单向”指使用 **因果 Mask**：在生成当前位置时不能偷看未来 Token。“多头”指注意力有多个头，二者不矛盾。训练阶段许多位置可以并行计算损失；实际自回归解码阶段通常需要依赖先前生成的 Token，因而输出存在序列化依赖。不能把“Transformer 并行”理解成所有 Token 一瞬间全部生成。

## 训练和检索是什么关系

大规模预训练优化下一 Token 预测，后训练阶段通过 SFT、偏好优化等改变模型行为。RAG 不改变底座权重，而在请求阶段检索当前证据并加入上下文。模型的知识记忆、可访问上下文窗口和外部检索数据库，分别属于三个层次。

长对话会不断消耗上下文，系统可能用摘要压缩或按需检索历史状态，但不能假定所有产品必然自动压缩；压缩可能丢失具体事实。应区分 Token 数量上限、摘要策略、持久化记忆与 RAG 的召回质量。

## 多模态为什么需要专门编码与对齐

图像通常经切片或视觉编码器形成特征序列，音频经波形/谱图等方式变成特征，视频还需要保留帧时间与音轨对应关系。它们都能进入某种联合表示或序列生成系统，但**音频、视觉、文本的编码方式并不完全相同**。

例如“谁说话时画面出现爆炸”需要同时定位音频中说话内容、视觉中事件与发生时间。单靠图片 Embedding 与文字 Embedding 的余弦相似度不足以完整回答。

## 机制如何用于新判断

检索错答先查知识版本和证据；延迟问题区分 Prefill 与自回归 Decode；视频不懂声音要确认模型是否真的支持联合音轨、时序输入。这些是把原理迁移到真实系统的具体判断方式。
