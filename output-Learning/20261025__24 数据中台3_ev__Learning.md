# Learning｜同一个数据中台怎样产出 RAG 知识、SFT 样本与 DPO 偏好对？

> 来源：`output/20261025__24 数据中台3_ev/content.md`。Learning V0.7.0，独立 Review 调用隔离未验证。

数据中台不应只有“一张万能数据表”。不同模型任务消费的数据形态不同：

**RAG** 需要可检索知识片段及其来源、权限、时间、实体关系，通常还需要 Embedding 和索引。它解决推理时“从哪里找证据”。

**SFT（监督微调）** 需要经过审核的示范输入与目标输出，例如 `messages=[user..., assistant...]`，用于训练模型模仿合适响应。它改变模型参数或适配器，不是在每次回答时重新查资料。

**DPO（直接偏好优化）** 一般需要在相同提示下的一组 `chosen`（偏好）与 `rejected`（非偏好）回答，使模型学习二者的相对偏好，而非单条正确答案。

因此，一份销售聊天可以先被清洗、授权和标签化，再按用途转换成不同数据产品；**同一份数据的质量标准不能机械复用**。例如适合全文检索的长文并不直接构成高质量 SFT 样本，偏好训练还需有可解释的正反对照。

媒体资产同理：图片与视频应带有素材 ID、SKU ID、授权状态及版本，并与知识表关联。运营 Agent 生成素材后，必须经审核发布才能进入客服可见库，避免未经确认的生成图直接用于真实销售。

真正要验证的是从原始记录到下游样本能否沿 ID 回溯，以及每一种输出是否符合其训练或检索目标。
