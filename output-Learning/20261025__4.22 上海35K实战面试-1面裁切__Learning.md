# Learning｜企业 AI 转型，什么应该由规则控制，什么交给模型？

> 来源：output/20261025__4.22 上海35K实战面试-1面裁切/content.md。Learning V0.7.0；独立 Review 隔离执行未证实。

商品 ID、库存、价格、权限和审批属于确定性业务事实与约束，应由后端服务核验。模型适合识别用户不完整的自然语言、解释证据、组织文案和从获授权工具中选择适当能力。两类职责不能因为搭建了 Agent 就混为一谈。

例如客户问某款鞋是否有货，先识别 SKU 并访问权威库存，再让模型组织回答；如果问“哪种适合跑步”，可使用语义检索和排序提供候选，但还需确认商品事实。

工作流并不与 Agent 对立：确定性节点控制重要状态转换，模型在可控节点做模糊判断。多 Agent 并行可以实现，但要隔离共享状态、明确写入权和合并冲突，不能认为并行必然失败。

企业遗留系统重构还需要将旧业务规则从代码、数据和员工经验中恢复出来，形成测试与验收标准。把规则写成 Skill 有助复用，但不替代权限检查、真实环境测试和回滚。一个贯穿请求的 Trace ID 有助定位错误发生在哪个环节。
