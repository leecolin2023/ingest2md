# Learning｜Agent 工作流怎样评测“路径对不对”，而不误杀合理的替代路径？

## 什么是轨迹评测

Agent 不仅产生结果，还经历意图判断、选择工具、执行动作、重试和异常处理。轨迹评测关注这些**中间动作是否符合任务约束**。

例如要求“根据批准的品牌素材生成鞋子海报”，一条理想轨迹可能是：查素材 → 撰写文案 → 生图 → 提交审核。若系统没查素材就编造品牌信息，即使海报看上去漂亮，也违反了关键过程要求。

## 为每个问题写死 ABC 顺序是否合理

对审批、支付、权限校验这类具有强顺序要求的流程，必须执行的动作可以设为硬约束。但对一般信息检索，先查产品参数再查用户评论，或者顺序相反，可能都合法。

因此黄金轨迹集不应仅包含一个固定字符串。更好的做法是记录：

- **必需事件**：哪些工具或验证不能跳过；
- **禁止事件**：哪些越权调用或危险动作不能发生；
- **依赖关系**：必须先完成 A 才允许 B；
- **质量与成本**：是否出现无用循环、过多调用或无法恢复的失败。

这使轨迹评测既有标准，又允许实际工作流采取合理替代路径。

## 为什么还要看结果

完全满足既定顺序也可能产生错误图片；不同顺序也可能得到正确结果。轨迹评测用于说明系统是否按照安全有效的方法执行，最终结果评测仍检查内容正确、符合品牌规范和用户要求。两者互补。

## 从粗到细的评测策略

先检查任务是否完成、关键工具是否被调用以及有无越权；再对重要失败案例下钻具体工具参数、知识片段、重试和模型判断。通过记录真实执行轨迹、比对规则及人工抽检，可以逐步建设可靠的 Agent 回归集。
