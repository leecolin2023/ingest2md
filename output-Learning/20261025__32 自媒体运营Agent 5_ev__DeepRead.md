# Deep Read｜限流、重试、熔断、降级如何嵌入 Agent 工作流

> 来源：`output/20261025__32 自媒体运营Agent 5_ev/content.md`（12分03秒）。遵循 Deep Read V6.4，保留作者解释顺序和案例。

讲者从简历上的一句话入手：“对 API 接口增加限流、熔断降级、指数退避重试和健康检查。”他没有只罗列术语，而是逐项说明运行机制。

首先是**限流**：用类似 SlowAPI 的装饰器或规则限制接口的单位时间调用次数，例如每分钟只允许请求五次。其目的包括控制昂贵的图片生成 API 成本、防止流量突增导致服务过载。

接着是**熔断**。他借电路开关介绍三个状态：闭合时请求正常经过；当近一段时间内错误比例太高，例如十次失败五次，转为断开以避免持续打向故障服务；随后进入半开，定期放少量测试请求检查服务是否恢复，再决定关闭熔断器恢复正常流量。

**降级**是换一条功能或能力较弱但仍能使用的路径。讲者举例图像生成主服务不可用时，逐步切换备用模型或供应商；RAG 向量通道故障时，可以退到精确关键词检索。

**指数退避重试**用于处理临时失败：不是每秒无穷重试，而是例如失败后等待一秒、两秒、四秒，达到次数上限后停止或进入后续保护逻辑。

随后讲者把这些策略放进 LangGraph 式 Agent 工作流，强调**不应每个节点机械套上相同保护**。相对稳定的意图识别可能主要需要超时保护；知识库检索可以结合降级通道；图片生成成本高、依赖外部不稳定接口，就可能同时需要限流、重试、熔断和备用服务。

结尾他认为健康检查这一条可以删去，面试展示时优先讲清关键节点策略。全文的核心是**可靠性保护应按照节点依赖、成本、故障模式和业务影响组合使用**，而不是在全部链路上统一开启所有开关。
