# Learning｜一个可恢复、可人工审批的 LangGraph Agent 怎样运作？

> 原稿：output/20261025__06 重学langchain02/content.md。参照 Learning V0.7.0；独立 Review 隔离未验证。

## 状态、节点和边

LangGraph 用状态承载消息、工具结果与业务字段；节点执行模型或工具逻辑，边和条件边决定下一步。典型工具循环为：模型节点决定是否请求工具 → 工具节点执行并将结果写入状态 → 返回模型节点 → 直到不再需要工具。

与纯函数链不同，Agent 可能经历多轮、失败、等待和恢复，因此必须持久化必要状态。

## Human-in-the-loop 为什么需要持久状态

例如模型准备执行高风险操作，程序在审批点中断，并保存关联会话与待执行动作。前端通过 API 获得“等待批准”的明确状态；用户确认后，携带授权身份、审批结果和任务 ID 请求恢复。后端校验授权，利用 Checkpointer 找回执行位置。

若只在前端显示弹窗，却没有后端审批约束，模型仍可能绕过确认；若恢复时不记录已执行动作，可能重复下单。真正的可靠性依赖后端权限和幂等，而非 UI 文案。

## Middleware 为什么比每个节点复制逻辑更好

调用限制、重试、消息修剪、隐私处理与日志记录可能发生在模型调用前后或工具调用前后。把它们收敛到可测试的中间件可减少重复，但必须理解钩子次序，不要把 after-model 误当作整个 Agent 工作流结束。

## 流式输出和持久化的区别

文本流告诉用户模型正在输出什么；事件流告诉开发者当前哪个节点执行；Checkpoint 则保存可恢复的业务状态。三个系统目标不同。

学会这一套链路的验收方式是：主动让工具失败、在人工审批点重启进程，再验证恢复后的状态、权限、输出和计费是否仍正确。
