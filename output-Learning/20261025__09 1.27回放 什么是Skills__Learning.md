## Skill 解决什么问题

普通提示词能告诉模型一次性任务目标，但在重复性专业任务里，还需要稳定的步骤、输入要求、边界、工具说明与验收规则。Skill 把这些知识组织成可以加载、复用和版本管理的文档或资源，使不同任务不必每次重新说明全部细节。

## Skill 与 MCP 的分工

Skill 偏向**执行方法与工作规范**：例如如何阅读财务报告、如何拆解长文、如何评测 RAG。MCP 更偏向**连接外部工具与资源的协议**，让模型所在宿主能够发现和调用受控服务。Function Calling 则是模型向宿主输出调用某项工具的结构化请求。

Skill 可以指导“何时用哪个工具、成功标准是什么”，却不能自己绕过宿主去访问文件系统、数据库或私有 API。工具具备能力，也不自动知道复杂业务流程怎么安排。

## 一个可迁移的运行过程

用户提出任务 → 宿主识别适合的 Skill → 读取其主规则及必要参考资料 → 模型按规则计划并调用获授权工具 → 对产物进行验收 → 记录版本与结果。

技能越多并不必然越好。应将稳定的、跨案例可迁移的原则放入主规则，将单一项目的例子放到测试资料中，以免技能过度拟合。

理解 Skill 的重点在于能解释**规则如何被加载、工具何时被授权、验收谁负责**，而不是只知道在目录中放一个 SKILL.md 文件。
