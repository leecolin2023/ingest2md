# Learning｜酒店 AI 前台如何在同一聊天中维护多个业务任务？

> 原稿：output/20261025__4.23 上海35K实战面试-2面裁切/content.md。Learning V0.7.0；独立 Review 隔离未验证。

聊天会话 ID 不等于业务任务 ID。用户在一个窗口可能先办理入住，到第三步又询问洗衣房，或者预约付费衣物送洗。后端应分别保留入住任务的当前节点、已提交参数与批准状态，也为新问题创建查询或服务任务。

意图识别负责判断当前表达对应哪项任务，不是直接授予执行业务的权限。“我要洗衣服”可能指设施位置，也可能指付费服务，必要时应向用户澄清。真正办理续住、退房或付费订单，需要业务系统校验身份、库存、价格与授权。

LangGraph 状态与 Checkpoint 可以帮助恢复中断的任务，不能代替订单数据库事务。MCP 可提供标准化工具接口，却不应绕过房间管理和支付审核。

跨系统记忆应区分短期会话状态与有授权的长期用户偏好。共享用户 ID 不代表各业务系统可以自由读取所有聊天。验收应验证中途插入问答后能返回原任务、不同服务不会串状态、失败或刷新不会重复执行付费动作。
