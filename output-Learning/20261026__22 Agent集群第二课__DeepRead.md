# Agent 集群第二课：从单个工具调用到企业共享 MCP 服务

> 原稿：`output/20261026__22 Agent集群第二课/content.md`（39:19）；Deep Read V6.4，Cognitive-Synthesis。保留讲师的架构推演，不把示例系统当作已部署事实。

## 从上一轮面试追问过渡到新课程

直播先回答前期真题：微调效果不佳时检查数据与训练参数；容器化部署、反向代理、云服务与高并发回答应结合所应聘项目。讲师随后转到当天的主题——让学员理解“Agent 集群”是什么，而不是立即进入具体代码。他表示会先提供概念材料，后续再用较小案例演示部署。

## 共有功能为什么值得抽出来

讲师从单个 AI 项目里反复出现的能力讲起：数据库查询、知识检索、模型调用、图像生成、文件处理、会话记忆、提示词管理、日志统计。假设企业有多个 Agent 应用，每个应用重复实现一遍，配置、升级与授权就被复制了很多次。于是，讲师提出把复用率高的能力封装成 MCP Server，由各 Agent 项目作为客户端调用。

他将 MCP 的组成概括成三个部分：Tools 供调用动作，Resources 供读取资源，Prompts 供复用提示词，并类比前端组件库或 NPM 包。这帮助初学者把“能力从项目内移到共享服务”具体化。

## 从一次用户咨询看调用关系

讲师以“上周购买的耳机尚未到货”为例：客户端首先识别用户和历史购买信息，再调用订单/物流查询能力，可能补充商品知识库信息，最后由模型将结果组织成回答。此例的关键并不是用几个 Agent，而是原本散落在多个业务系统里的能力，现在可通过相对统一的调用接口供不同项目使用。

## 将复用做成平台后出现新的责任

共享服务不再只关心单项目是否跑通。讲师展示五个层次：

- 接入层：客服、销售等使用 MCP 的具体 Agent 项目；
- 网关层：统一鉴权、流量控制、路由、费用或 token 统计；
- 共享服务层：检索、文件、模型、记忆、工具注册等能力；
- 基础能力层：模型 API、embedding、缓存及执行基础设施；
- 存储层：数据库与日志系统。

他依次延展出命名空间隔离、统一对话记忆、提示词版本管理、语义缓存、工具注册发现、访问控制、跨服务 Trace、成本统计、评测、高可用、熔断降级、灰度发布等问题。随着项目数量增加，复用的收益与共享故障的影响范围会一起扩大。
