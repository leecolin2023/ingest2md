# Deep Read｜提示词管理、MCP Resources 与对话持久化

> 来源：`output/20261025__36 MCP集群4_ev/content.md`（4分31秒）。Deep Read V6.4。

讲者首先介绍 MCP 集群的最后一个组成部分：**统一提示词管理**。不同项目都需要客服或销售引导指令，可以把通用系统提示词按名称、描述和参数封装，由中心服务管理，避免每个项目手写一套。修改公共模板后，多个调用方能够使用同一套配置。

他特别强调，模板指令与用户的聊天上下文不是同一回事。用户历史消息应存于数据库或专门的会话存储，而不应该把个人对话写进公共系统提示词模板。

随后讲者提到 MCP 的 **Resource** 概念，认为可以把文件或数据库里的资料作为对外可读取的资源。他进一步设想通用会话管理服务，以用户 ID、系统 ID、对话 ID 为参数，检索历史消息，让用户刷新后仍能延续对话。

最后，他将“多个系统反复需要的能力”作为通用 MCP 服务抽象的标准，并鼓励学员结合企业实际业务自行设计更多公共工具。视频并没有提供 MCP Prompt/Resource 与数据库读写工具之间的完整协议区别。
