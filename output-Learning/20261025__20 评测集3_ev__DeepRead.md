# Deep Read｜讲者怎样把检索黄金数据集用于 Top-N 过程检查

> 来源：`output/20261025__20 评测集3_ev/content.md`（8分51秒）。Deep Read V6.4。

讲者重新回到黄金数据集的例子：准备 50 个问题，知识库中有 500 条带 ID 的记录，平均一个问题有若干相关片段。实际检索链是**Top-K 粗召回 → Rerank 精排 → Top-N 交给模型**。

他强调评测不能只看第一阶段是否捞回正确片段，还要看经过精排后最终送给模型的 Top-N。例如“我大专可以学吗”的标准上下文是 ID10、11、12，实际 Top-N 也应该包含这些关键证据，否则模型拿到的是不相关的“小抄”，难以写对答案。

这里他用考试比喻多次解释：即使考生知道如何答题，带错了学科的小抄也帮不上忙。但**小抄正确仍不能确保最后试卷分数相同**；不同模型、不同人即使使用同一参考材料，最终开放式表达也不一定完全一样。

讲者进一步把整个客服效果归因于意图识别、系统提示词和 RAG 检索三个环节，主张先确保前两项相对稳定，再关注黄金片段是否在 Top-N 命中。他由此反对把“生成的文字必须与标准答案字面一致”作为唯一评测方法，认为**过程证据**更可控。

原文虽反复使用“模型评测核心就是过程”，但本视频没有证明最终答案评测不重要；它真正提供的是如何设计**检索链中间状态的可观测与标注**。
