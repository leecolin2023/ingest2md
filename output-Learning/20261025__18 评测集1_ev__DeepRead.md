# Deep Read｜讲者为何把 RAG 评测概括为输入、检索、输出三个要素

> 来源：`output/20261025__18 评测集1_ev/content.md`（2分43秒）。Deep Read V6.4。

课程从一个面试问题开始：“你是如何把握大模型回复质量的？”讲者先借传统单元测试介绍输入—输出关系，例如函数接收 2 和 3，预期返回 5。这个简单例子为后续 RAG 的评测引出第三个要素。

讲者认为在 RAG 客服里，仅看问题和最终答案还不够，应把**命中的知识资料**也纳入观察。因此他给出“三元组”的教学框架：**用户输入 → 检索命中的 RAG 片段 → 生成输出**。例如问题“我大专可以学吗”、中间的多个课程案例片段、最终回答“可以学”。

他随后发表一个较强的观点：如果没有 RAG、只调用云厂商通用大模型，就没必要自己评测，因为服务商会负责通用模型的评估。视频并未展开其他业务约束，因此应把它视为讲者为教学聚焦 RAG 所作的判断，而不是所有 LLM 应用的普遍原则。

整节课的独立认知单元不多：以单元测试类比为入口，引入 RAG 检索中间层，再宣布后续围绕这三类记录设计评测集。
