# Deep Read｜从 RAG 片段检查扩展到 Agent 工作流轨迹评测

> 来源：`output/20261025__21 评测集4_ev/content.md`（8分48秒）。Deep Read V6.4。

讲者先回顾既有的文本忠实度、图片质量、Agent 轨迹和 Ragas 等评测方法，认为这些内容应作为补充知识，但实际面试不必铺开全部评测框架；应抓住对当前项目最有价值的两个点：**黄金知识片段命中**和**业务流程是否走对**。

接下来用 LangChain/LangGraph 工作流举例：用户要求“生成一张鞋子的海报”，理想流程可能是调用 Agent A、B、C 完成素材准备、文案和图片；实际执行却可能是 A-D-B-C、A-A-B-B-C-C 或完全偏离到 E-F-G 等节点。讲者因此建议构造**业务流程黄金数据集**，为每个用户意图事先标出预期节点序列，实际执行后检查有没有走偏、重复调用或漏掉必要步骤。

他进一步讨论**评测粒度**：粗粒度只看 Agent A 是否被调用；细粒度还要看 A 内部使用了什么 RAG 资料、如何调用工具。业务越复杂，轨迹评测工作量越大，所以应根据业务风险和成本决定监控深度，先粗后细。

最后他谈 AI 应用开发与 AI 测试人员分工，认为复杂评测可能需要专门的测试开发岗位；项目开发者至少应理解如何构建知识库黄金集和业务流程黄金集，并能在面试中解释判断逻辑。
