## 二、关键发现（影响理解或行动）

### 1. "把 rm -rf 写进 deny，任何时候都执行不了"——过度承诺，会误导安全边界认知

- 官方文档的准确表述是：bash 规则匹配"模型写出的命令文本"；**"它不匹配同一程序的不同调用形式，deny/ask 规则覆盖的只是 Claude 通常写出的那种调用，并不是围绕该程序的安全边界"**（原文："isn't a security boundary around the program"）。文档给出的反例：`Bash(git push *)` 挡不住写成 `git -C . push` 的推送。同理，`rm -rf` 换个参数顺序或包装、写进脚本再执行（`bash cleanup.sh`）、或经由其他写文件的工具达成同样效果，都可能不命中该条规则。
- 这一句的前半段（"allow 规则没法给 deny 规则开例外"，且 deny 在所有模式下生效）是对的；问题在后半段的绝对化表述。
- **影响**：听众会以为"写了 deny 就万无一失"，从而省略沙箱、容器这类真正的隔离措施——而这恰恰与视频后半段自己的结论（"真正的安全来自限制 agent 能访问的文件、凭证、进程和网络"）相矛盾。
- **修正**：改为"deny 规则能稳定挡住模型常规写法，是降低误操作概率的护栏；它不是安全边界，边界靠沙箱和隔离"。

### 2. 分类器只引用了"误报率"这一半数据，没有给风险侧的数字

- 8.5% → 0.4% 确为 Anthropic 官方数据，口径是"误报（误拦正常操作）"。用它论证"少打扰用户"是**用对了指标**；但同一张表里还有漏报侧：对真实"过度主动"动作的漏检率 **17%**（官方博客自称"诚实的数字"），对合成外泄任务的漏检率 5.7%。视频把分类器定位为"规则判断不了的操作的**审查者**"（安全职责），却只给了摩擦侧数字、没给风险侧数字——听众容易把"分类器审过"理解为可靠安全阀。
- 同类边界值得知道：Anthropic 自己明确说 Auto 模式降低风险但不消除风险、仍建议在隔离环境使用；2026 年 4 月一篇独立压力测试（arXiv:2604.04978，128 个模糊授权任务、253 个状态变更动作）测出端到端漏检 81%——该数字是**对抗性压力测试口径，与生产口径的 17% 不可直接比较**，不能据此断言分类器"不行"；但它揭示了一个结构性事实：**36.8% 的状态变更动作来自分类器根本不审的"项目内文件编辑"通道**（清理类任务漏检 92.9%）。
- **影响**：这不会推翻"用分类器替代人工审批"的方案，但会改变信任定级——正确的表述是"分类器把打扰和误拦降到很低，但漏检非零且不覆盖项目内文件编辑，高风险动作仍需沙箱/审批兜底"。这句话视频最后一段其实已经说了（"用边界代替审批"），只是前面没有点破，两段之间缺少衔接。
- **修正**：在分类器段补一句——"这是摩擦侧指标；官方同样披露了对危险动作约 17% 的漏检率，所以它降低而不是消除风险，兜底仍是沙箱"。

### 3. "项目内编辑直接放行、改错 git 撤回就行"的两个隐含前提未说

- (a) 放行并非无条件：Claude Code 的受保护路径（`.git`、`.claude` 等）即使匹配 allow 也仍会走审批/分类器；"项目目录内"也以工作目录与额外目录为界。
- (b) "git 撤回"的前提是目标文件受版本控制、且改动尚未被执行生效。删除**未跟踪文件**无法用 git 恢复；对脚本、配置、CI 文件的"可回滚"编辑，在被后续执行后并非简单可逆（独立压力测试里这类通道正是漏检重灾区）。
- **影响**：把等号补全前提后，分级准则依然成立，但"自动放行编辑"的信任强度需要下调一档——这也是"可回滚 = 事后通知即可"这条建议对个人开发者容易产生的一个乐观偏差。
- **修正**：在例证处补半句："前提是文件已纳入版本控制、且改动没有被执行生效；未跟踪文件和脚本类文件不适用"。

## 三、次要发现（不改变主线，按需采纳）

1. **"只读操作直接执行"需要范围限定**：只读在工作目录及额外目录内才免问，工作目录外、网络路径的读取会触发管控；且"读取"本身可构成外泄链路的一半（读取凭证 + 对外发送），需要配合网络限制与 deny 规则一起看。
2. **提示词注入的归因略偏**：分类器不看工具结果，保护的是"分类器自己不被注入内容操纵"；针对 agent 本身的注入防线是输入侧探针与边界隔离。视频后文有沙箱兜底，方向不冲突，但"不看工具结果 ≈ 很大程度防止提示词注入"的因果表述不精确（工具结果本来就会进入 agent 的上下文——否则上一句"被拦截的操作会作为工具结果返回给模型"就不成立）。
3. **"我都是直接给的最大权限"缺隔离环境前提**：官方立场是跳过全部权限审批只应在隔离环境使用；视频后段给了容器/微虚拟机的建议，但未与前句挂钩，口播稿在二次传播中容易被断章取义为"建议梭哈"。
4. **小漏一项**：分类器的输入除用户消息与工具调用外还包括 CLAUDE.md（对结论无影响）。
5. **"修改"节点未展开**：定义提到"批准、修改或拒绝"，正文只讲了批准/拒绝两条路径，"修改后继续跑"（含 LangGraph `Command(resume=...)` 可携带修改值）没有涉及——按三分钟体量属可接受裁剪，若做系列可作后续内容。
6. **幂等是必要条件但不是唯一手段**：LangGraph 官方同时建议把副作用放到 interrupt 之后、或拆分到独立节点；视频只给出"必须幂等"，作为入门建议正确，作为工程清单可再补一句。
