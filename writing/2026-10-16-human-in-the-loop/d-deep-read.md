原文是一条按"模拟面试题"层层推进的连续论证，以下沿它自己的推进顺序重构。

## 起点：会弹窗，不等于会设计

- 面试题：HITL 怎么设计？若答"危险操作之前弹窗，让用户确认一下就行"，出局。
- 原因：**弹窗弹多了人会烦**。讲者自述很讨厌 agent 的弹窗——"都已经人工智能了，直接 auto 梭哈到底"——他本人对 Claude Code、Codex 都是直接给最大权限。于是"怎样少打扰用户"成为后面逐层展开的问题。
- HITL（人在回路）的含义：在 agent 的执行过程中设置一些需要人来做决定的节点——批准、修改或拒绝——然后再让 agent 接着执行。
- 真正的难点不在弹窗本身，而在**哪里该弹、哪里不该弹**。

## 问题一：哪些操作必须等人点头——按风险与可逆性分级

候选答案（所有写操作／除只读操作以外的全部操作／按风险和可逆性分级）中，正解是**按风险和可逆性分级**，落实为三级：

1. **只读操作**（读文件、搜索代码）：直接执行。
2. **可回滚的写操作**：事后通知即可。例：Claude Code 的 Auto 模式对项目目录里的文件编辑直接放行，改错了用 git 撤回就行。
3. **不可逆操作，以及涉及资金、权限、对外发送的操作**（如删除数据库、转账、群发邮件）：**必须事前审批**。审批内容要具体、清晰——把完整的命令、要修改的文件、订单的金额展示出来，让用户看一眼就知道自己需要批准什么。

## 问题二：怎么才能少打扰用户——三个手段都要上

候选答案（记住授权／把规则写在前面／交给另一个模型审查）的答案是：**三个都要**。

1. **记住授权**。Claude Code 的审批弹窗里有一个选项叫 "Yes, and don't ask again"，选了它，bash 命令的授权会写进仓库根目录的 `.claude/settings.local.json`，下次遇到同样的命令就不再询问。
2. **把规则写在前面**。Claude Code 的权限规则分 `deny`（拒绝）、`ask`（询问）、`allow`（允许）三种，按 deny → ask → allow 的顺序匹配，先匹配上哪一条就按哪一条执行。注意：**allow 规则没法给 deny 规则开例外**——所以把 `rm -rf` 这类命令写进 deny，就任何时候都执行不了。
3. **交给另一个模型审查**（也是 Auto 模式的做法）。规则判断不了的操作——比如 shell 命令、网络请求、项目目录以外的文件操作——交给分类器模型：
   - 分两个阶段：第一阶段只输出一个 token，判断要不要拦截；被标记了，才进入第二阶段做推理。
   - 效果（据 Anthropic 官方博客数据）：误报率从 **8.5% 降到 0.4%**。
   - 关键细节：分类器**只看用户的消息和 agent 的工具调用，不看工具返回的结果**——因为网页和文件里可能藏着恶意指令，不把工具结果注入上下文，能在很大程度上防止提示词注入攻击。

被拦截之后的走向：拦截结果会作为工具结果返回给模型，让它换一种更安全的做法；**连续被拒绝 3 次，或累计被拒绝 20 次**，agent 就停下来，交给用户处理。

## 问题三：等用户确认时，agent 怎么停下来——保存状态后退出，回复后再继续

候选答案（在 agent loop 里 sleep 等用户回复／保存状态后退出／让模型自己再问一遍）中，正解是**保存状态后退出，用户回复以后再继续**。

理由：审批可能要等几分钟，也可能要等到第二天；进程如果一直挂在那里等，一旦服务重启，任务就没了。

两家框架的具体做法：

- **OpenAI Agents SDK**：给工具设置 `needs_approval`，模型调用这个工具时，运行就会暂停；结果里的 `interruptions` 会列出待审批的工具调用；调用 `to_state` 方法转成 `run_state`，再用 `to_json` 方法存进数据库；用户批准以后取出来，调用 `approve` 或 `reject`，再交给 Runner 接着执行。
- **LangGraph**：用 `interrupt` 函数，调用时把整张图的状态存进 checkpointer（也就是状态存档器）；用户回复以后，用 `Command` 带上 resume 的值恢复执行。

**LangGraph 有一个坑**：恢复时不是从 interrupt 那一行接着执行，而是把**整个节点从头执行一遍**。如果你在 interrupt 之前就扣了款，恢复以后就会再扣一次——所以 **interrupt 之前的操作必须幂等**，就算重复执行，也不会影响结果。

## 追问：全自动场景没人审批怎么办——用边界代替审批

原文提到一个默认不做权限审批的 agent（转写中仅以"这个 agent"指代，未点名），它的安全文档写得很清楚：没必要一直盯着对话记录、审查改动；**真正的安全来自限制 agent 能访问的文件、凭证、进程和网络**，并推荐把它放进容器或者微型虚拟机里运行。

确实需要审批，就装上 **Permission Gate 扩展**：在 `rm -rf`、`sudo` 这类命令执行之前弹窗确认；此外还有配套手段——沙箱限定 agent 只能在权限范围内做事情、白名单决定哪些操作不用咨询用户、事后审计把每一步操作记下来（出了问题能查清楚）。

## 收束

原视频的一句话总结：**撤不回的操作等人点头，撤得回的操作交给规则和沙箱。**
