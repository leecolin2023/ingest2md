### 00:00–03:29

字节、阿里、OpenAI 岗位面试必考，面试官问你 Agent 意图路由怎么设计？如果你回答把所有子 Agent 的介绍写进提示词，让大模型自己选一个，恭喜你出门右拐回家等通知，90% 的初学者都卡在这一步。看似简单的路由问题却是区分业余 demo 和生产级 Agent 的核心分水岭，今天带你吃透大厂标准答案，从底层原理到落地架构。听完面试直接脱口而出，吊打 99% 的竞争对手。

首先我们搞懂核心本质，到底什么是 Agent 意图路由。很简单，用户发来一句话，系统第一步要做的就是判断请求归属，给用户的需求精准分流，就像电商客服 Agent 背后挂着查单。查订单、退换货、售后咨询等多个 Agent，还有不同的工作流分支、高低成本模型，把用户请求精准分配给对应处理路径的这一步就是意图路由。讲到这里，很多同学还是会懵，不同场景到底该用哪种路由方式，避坑要点根本记不住。

我整理了一份 AI 大模型 200 万字面试宝典，里面涵盖了 30 多个技术栈，包含 RAG、模型微调，想要转型 AI 的同学留 AI，直接无偿分享。很多新手无脑把路由全丢给大模型，这是最大的误区。之前全网吐槽的 AI 客服 bug，用户随便发两句 hello，20 刀订阅费用就没了，根源就是纯大模型路由的不可控、高成本、低精准度。

肯定有人好奇那 OpenAI 官方是怎么做路由的，记住不是写单独路由函数，也不是简单调用工具。

OpenAI 开源的 Agent SDK 里负责分流的角色叫分诊 Agent，SDK 会把每一个子 Agent 包装成一个工具，工具名字是 transfer_to 加上子 Agent 的名字，比如 transfer_to_refund_agent，工具描述写着把请求移交到对应子 Agent 处理，后面带子 Agent 介绍。

分诊 Agent 选中哪个子 Agent 就调用对应的工具，这种把对话交给另一个 Agent 接手的动作，SDK 里叫路由。路由准不准，全看每个子 Agent 的简介写得清不清楚。官方明确建议分类路由任务，尽量用枚举参数。结构化输出限制模型只能在给定选项里面选择。

接下来重点讲生产级 Agent 的路由设计，四种方案分层使用，这才是字节面试官最想听的高分答案，分别是规则路由、向量比对路由、决策模型路由、大模型路由，由轻到重，逐级判断，绝不滥用大模型。第一，规则路由。像查订单退款这种关键词明确的请求，直接用规则处理，响应成本极低。

第二，向量比对路由就是这么实现的，不需要调用大模型，提前给每条路由准备对应的示例问句，用户问题进来先转向量，匹配最相近的几条示例，按所属路由计算平均分，分数超过阈值就走这个路由。第三，轻量决策模型路由。Type AI 给出的数据延迟 70 到 500 毫秒，Open Decisions API 单次任务只要 150 毫秒，对比大模型一点几秒的延迟，优势巨大。

最后才轮到大模型，前面三种方式都判断不了的模糊请求，再交给大模型，简单请求交给便宜模型，复杂请求再上强能力大模型。一句话记住，能用向量比对和决策模型解决的就不要上大模型。面试官还会继续追问，路由不准确或者冲突了怎么办？比如用户一句话，同时命中退款和查订单两个意图，分数都不高，记住，不要直接选分数高的，也不要两个全部执行。正确做法，拿不准就带上选项去反问用户。同时， 要有回退机制。

子 Agent 遇到超出自己范围的问题，可以把对话转回分诊 Agent 重新分配，但是一定要设置转回次数上限，防止多个 Agent 来回踢皮球。工单路由指南也提到，一个请求包含多个意图，要提前约定优先级；意图类型超过 20 个，就要分层分类，先分大类再细分小类。另外要准备标注好意图的测试数据集，统计每个意图的准确率和召回率。

行业实测把向量库中和当前问题相似的标注样例放进提示词，准确率可以从 71% 提升到 93%。最后一个高频追问，让模型自己输出置信度靠得住吗？记住结论：靠不住。可信的置信度。要靠这几种方式实现。第一，读取模型输出每个选项的对数概率，也就是 logprobs，OpenAI 官方文档的方案，概率超过阈值自动分类，低于阈值转给人工复核。第二，直接使用向量比对得到的相似度分数。

第三，使用经过校准的决策模型，校准的含义就是模型说 90% 把握的时候，实际正确率也接近 90%。最后给大家总结一句，可以直接背的面试金句：确定的场景用规则，相似的场景用向量，固定选项用决策模型，模糊请求交给大模型，拿不准的直接问用户。吃透这套生产级 Agent 路由设计思路，你的 Agent 面试，直接甩开九成竞争者。
