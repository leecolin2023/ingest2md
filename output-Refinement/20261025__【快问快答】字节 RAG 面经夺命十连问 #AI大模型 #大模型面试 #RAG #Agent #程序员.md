今天聊一份字节 RAG 面经的“夺命十连问”。总共十道题，前面偏基础，后面更考验项目落地经验。很多候选人会背概念，但一问到实际设计就说不清楚，看看你能回答到第几轮。

**1. 生产级 RAG 系统架构怎么设计，核心组件和数据流怎么讲？**

不要一上来堆技术栈，要先讲分层逻辑。我把 RAG 拆成四层：数据处理层、检索召回层、生成推理层、监控管控层。

文档首先进入数据处理层，进行格式解析、清洗、切片和向量化，分别进入向量数据库与业务知识库，就像仓库先理货再上架。用户查询进入检索层，先做意图识别和查询改写，再进行多路召回与重排，筛选相关知识片段。生成层拼接 Prompt，调用大模型生成答案，经事实校验后返回。管控层负责全链路埋点、效果监控、日志审计和故障兜底。

我还整理了一份包含 RAG、微调、Transformer、DeepSeek 和 Agent 项目方案的面试题库，有需要的粉丝可以留言“666”。

**2. 文档切片 Chunk 大小怎么定？**

没有通用标准，关键是平衡语义完整性和检索精准度。客服 FAQ 可以切成 200～400 字的小片段，方便精准匹配；技术文档可以切成 600～1000 字，保留段落逻辑；合同规章适合依据章节、条款做结构化切割。入门可以用固定长度切片；更复杂的生产场景可以用语义切片，避免硬切断上下文。

**3. 向量检索召回率低、答非所问，怎么优化？**

不要只调大 Top-K。先检查切片粒度是否合理、向量模型是否适合业务、索引配置是否生效。然后考虑查询改写，补充用户隐含意图，结合向量检索和关键词检索进行多路召回，再引入 Rerank 二次精排。垂直业务还应把类目、权限、时效等规则纳入排序，不能只依赖语义相似度。

**4. RAG 幻觉怎么治理，有哪些兜底手段？**

可以区分检索缺失导致的信息不全，以及模型自行编造的内容。检索侧提高召回覆盖率、做实体关联补全；生成侧通过 Prompt 限制回答依据，资料未提及就说明无法回答，并绑定引用溯源；兜底侧加入事实一致性校验，低置信度结果触发拒答或兜底话术，核心业务设置人工审核。

**5. Rerank 怎么选，什么时候要加？**

轻量、高并发场景，可以考虑 Bi-Encoder 做快速相关性判断；高精准要求场景，可以使用 Cross-Encoder 做深度重排，但延迟和计算成本更高。作者认为，当多路召回噪声较大、Top-K 候选超过 20，或者答案准确性要求高时，尤其值得考虑重排，就像招聘时笔试之后还要复试。

**6. 几十页、上百页的长文档，RAG 怎么做到精准又不丢上下文？**

不要只用扁平切片。可以采用父子层级切片：父片段按章节或较大区块保留上下文，子片段用于定位具体证据。查询时先定位相关章节，再找到关键句，最后把关键句连同必要的父片段上下文一起送给模型。还可以预先解析目录，建立结构化索引，辅助定位。

**7. 多租户 RAG 怎么实现数据隔离和权限管控？**

根据需求选择三级隔离：弱隔离是在单库中按租户 ID 过滤；中隔离是每个租户独立索引；强隔离是独立部署向量库实例。前者成本低，后者隔离程度更高。无论哪一层，检索前都必须检查权限，不能跨租户召回内容。

**8. 知识库频繁更新，怎样保证一致性和时效性？**

### 05:00–06:25

建立分级更新机制：高频变动内容做增量更新，新增或修改时触发向量化；低频数据按天或按周定期全量更新；核心数据先在测试库验证，再灰度切换。每份文档绑定版本号，更新失败能够回滚，避免脏数据进入线上知识库。

**9. 高并发情况下，RAG 接口响应慢，怎么优化？**

不要只盯着大模型推理，要看全链路 P95 延迟的主要瓶颈。高频查询可以使用语义缓存；向量库可以做冷热分离，让热点数据优先留在内存索引；检索与生成解耦，长任务异步化，并支持流式返回。非核心场景可降级到轻量模型，还要设置超时和熔断，避免个别长查询拖垮接口。

**10. RAG 效果怎么量化评估？**

建立全链路指标体系。检索侧看召回率、精准率、Top-K 命中率；生成侧看答案准确率、幻觉率、引用覆盖率；业务侧看问题解决率、用户满意度以及 Bad Case 占比。自动评估与人工抽检结合，定期回归分析 Bad Case。系统效果不能只凭感觉判断，要有数据支撑。
